# Toolward 规则目录

本文件由 `toolward rules --format md --lang zh` 生成，请勿手工编辑。

## 提示词注入与工具投毒

| 规则 | 默认严重度 | 标题 |
| --- | --- | --- |
| `TW101` | 高危 | 面向 agent 的内容里出现指令覆盖文本 |
| `TW102` | 高危 | 不可见 Unicode 字符 |
| `TW103` | 严重 | 双向文本控制字符（Trojan Source） |
| `TW104` | 高危 | 混合字符集命名（同形字风险） |
| `TW105` | 中危 | 藏在注释/不可见标记里的指令 |
| `TW106` | 严重 | 面向 agent 的内容里出现数据外带指令 |
| `TW107` | 高危 | 跨工具劫持（shadowing）指令 |
| `TW108` | 高危 | 要求对用户隐瞒行为的指令 |
| `TW109` | 高危 | 伪造的系统/权威标记 |
| `TW110` | 低危 | 工具描述过长 |

### TW101 — 面向 agent 的内容里出现指令覆盖文本

在 agent 会当作权威读取的内容里，发现试图覆盖宿主系统提示词的文本。

**修复:** 删掉这类覆盖措辞。工具描述和 skill 只应描述能力，不应重新定义 agent 的规则。

**参考:** <https://genai.owasp.org/llmrisk/llm01-prompt-injection/> · <https://invariantlabs.ai/blog/mcp-security-notification-tool-poisoning-attacks>

### TW102 — 不可见 Unicode 字符

零宽字符、软连字符或 Unicode tag 字符可以夹带人眼完全看不见的指令。

**修复:** 删掉这些字符后重新审阅纯文本。正常的工具描述不需要它们。

**参考:** <https://invariantlabs.ai/blog/mcp-security-notification-tool-poisoning-attacks>

### TW103 — 双向文本控制字符（Trojan Source）

Bidi 覆盖字符会让渲染出来的文本和机器实际读取的字节不一致，你审过的描述并不是真正生效的那份。

**修复:** 删除全部 U+202A–U+202E 与 U+2066–U+2069 字符后重新阅读文件。

**参考:** <https://trojansource.codes/>

### TW104 — 混合字符集命名（同形字风险）

工具名或服务器名把拉丁字母与西里尔/希腊字母混用，可以逐字伪装成一个可信名字。

**修复:** 改用纯 ASCII 命名，并确认你装的确实是你想装的那个包。

### TW105 — 藏在注释/不可见标记里的指令

HTML 注释、零号字或与背景同色的标记在渲染时看不见，但模型能完整读到。

**修复:** 删掉隐藏块。如果内容确实需要，就写成可见的正文。

**参考:** <https://genai.owasp.org/llmrisk/llm01-prompt-injection/>

### TW106 — 面向 agent 的内容里出现数据外带指令

这段文本指示 agent 读取本地机密或把数据转发给第三方——这正是工具投毒攻击的核心。

**修复:** 不要安装这个扩展。如果是你自己的，删掉该指令，把真实的数据流改成显式、有文档的参数。

**参考:** <https://invariantlabs.ai/blog/mcp-security-notification-tool-poisoning-attacks> · <https://genai.owasp.org/llmrisk/llm01-prompt-injection/>

### TW107 — 跨工具劫持（shadowing）指令

这段文本试图改变 agent 使用其他工具的方式，让一个扩展劫持本应发给另一个工具的调用。

**修复:** 工具描述只能描述自身行为。删掉对其他工具调用顺序的干预。

**参考:** <https://invariantlabs.ai/blog/mcp-security-notification-tool-poisoning-attacks>

### TW108 — 要求对用户隐瞒行为的指令

要求 agent 静默行事的扩展，会瓦解所有 agent 宿主赖以生存的人工确认环节。

**修复:** 删掉这类保密措辞。值得静默执行的操作，更值得一次确认。

**参考:** <https://invariantlabs.ai/blog/mcp-security-notification-tool-poisoning-attacks>

### TW109 — 伪造的系统/权威标记

<IMPORTANT>、[SYSTEM] 这类标记在冒充宿主自身的提示词结构，以借用它的权威。

**修复:** 从描述和 skill 正文中删除伪系统标记。

**参考:** <https://invariantlabs.ai/blog/mcp-security-notification-tool-poisoning-attacks>

### TW110 — 工具描述过长

超长描述既吃上下文预算，也正好是埋指令的好地方。

**修复:** 把工具描述控制在约 1000 字符内，细节放到文档里。

## 供应链

| 规则 | 默认严重度 | 标题 |
| --- | --- | --- |
| `TW201` | 中危 | 每次启动 agent 都会执行未锁版本的包 |
| `TW202` | 高危 | 从非官方registry源安装的包 |
| `TW203` | 严重 | 把远程脚本直接管道给 shell 执行 |
| `TW204` | 高危 | 疑似仿冒知名 MCP 包（typosquat） |
| `TW205` | 高危 | 通过明文 HTTP 连接远程 MCP 服务器 |
| `TW206` | 中危 | 插件市场/插件来源未锁定 |

### TW201 — 每次启动 agent 都会执行未锁版本的包

npx/uvx 这类运行器每次启动都会重新解析包，后续发布的恶意版本无需你做任何操作就会落到你机器上。

**修复:** 锁死确切版本（如 `pkg@1.4.2`、`pkg==1.4.2`），升级前先人工过一遍。

**参考:** <https://owasp.org/www-project-top-ten/>

### TW202 — 从非官方registry源安装的包

git URL、tarball、本地路径会绕开 registry 的校验、来源追溯和撤包机制。

**修复:** 发布到你能控制的 registry，或把代码 vendor 进仓库，让它能在 diff 里被审阅。

### TW203 — 把远程脚本直接管道给 shell 执行

`curl … | sh` 等于把任意的、没审过、没版本的代码交给开发机完整执行。

**修复:** 先下载、按校验和锁定、人工审阅，再作为独立且入库的步骤执行。

### TW204 — 疑似仿冒知名 MCP 包（typosquat）

包名与流行 MCP 服务器只差一两个字符，这是最典型的安装期劫持手法。

**修复:** 安装前对照上游项目 README 核对包名，并确认发布者。

### TW205 — 通过明文 HTTP 连接远程 MCP 服务器

工具描述、参数和鉴权头全部明文过网，且可在传输途中被改写。

**修复:** 改用 https://，或把服务器放在 localhost。

### TW206 — 插件市场/插件来源未锁定

指向浮动分支的插件来源，会在安装时装上该分支当时的任意内容。

**修复:** 改为引用 tag 或 commit SHA，不要用分支名。

## 密钥与凭据

| 规则 | 默认严重度 | 标题 |
| --- | --- | --- |
| `TW301` | 严重 | agent 配置里硬编码了凭据 |
| `TW302` | 高危 | 源码/skill/文档里出现凭据 |
| `TW303` | 高危 | 扩展读取本机敏感文件 |
| `TW304` | 中危 | 把整个环境变量转发给服务器 |

### TW301 — agent 配置里硬编码了凭据

agent 配置比 .env 更容易被提交、同步和分享，放在这里的有效密钥基本等于已经公开。

**修复:** 把值改成环境变量引用（`${VAR}`）或系统钥匙串，并立刻轮换已暴露的密钥。

### TW302 — 源码/skill/文档里出现凭据

仓库里任何位置提交过的密钥都会永久留在历史里，删文件也拿得回来。

**修复:** 先轮换凭据，再从 git 历史里彻底清除——只删掉那一行是不够的。

### TW303 — 扩展读取本机敏感文件

SSH 私钥、云凭据、浏览器 cookie、shell 历史，是被攻陷扩展最常拿走的东西。

**修复:** 去掉这类访问。确实需要凭据时，应作为显式参数传入，并写明作用范围。

### TW304 — 把整个环境变量转发给服务器

把整个进程环境传过去，等于把 shell 里所有无关密钥一并交给该服务器。

**修复:** 只列出该服务器真正需要的变量。

## 执行与权限

| 规则 | 默认严重度 | 标题 |
| --- | --- | --- |
| `TW401` | 高危 | 用不可信输入拼接 shell 命令 |
| `TW402` | 严重 | 权限/沙箱绕过标志 |
| `TW403` | 高危 | 对工具调用的无差别自动放行 |
| `TW404` | 中危 | 钩子以宽泛匹配器在每次事件上运行 |
| `TW405` | 高危 | 持久化驻留或自改 agent 配置 |
| `TW406` | 高危 | 文件系统授权范围过大 |
| `TW407` | 高危 | 动态代码求值 |

### TW401 — 用不可信输入拼接 shell 命令

扩展内部用字符串插值拼出的 shell 调用，会把任何由模型控制的参数变成任意命令执行。

**修复:** 改用 argv 数组式 API（`execFile`、不带 `shell: true` 的 `spawn`、`subprocess.run([...])`），并校验输入。

**参考:** <https://cwe.mitre.org/data/definitions/78.html>

### TW402 — 权限/沙箱绕过标志

这些标志会关掉 agent 宿主对所有危险操作赖以生效的人工确认与沙箱。

**修复:** 删掉该标志。确实需要的流程，请放进一次性容器里跑，绝不要放在开发机上。

### TW403 — 对工具调用的无差别自动放行

通配符放行清单，会把「被投毒的工具描述」与「在你机器上的真实动作」之间的最后一道关卡去掉。

**修复:** 改成逐个工具、逐条命令前缀放行，不要用 `*`。

### TW404 — 钩子以宽泛匹配器在每次事件上运行

匹配器为 `*` 的钩子能看到每一次工具调用及其参数，并且在你确认之前就已经运行。

**修复:** 把匹配器收敛到真正需要的工具上，并让钩子命令保持简短可审。

### TW405 — 持久化驻留或自改 agent 配置

写入 shell 配置、cron、launch agent 或宿主自身的设置，会让扩展在被删掉之后依然存活。

**修复:** 去掉这类写入。安装步骤应当是有文档、由用户手动执行的命令，而不是藏在工具调用里。

### TW406 — 文件系统授权范围过大

把 `/`、`$HOME` 或 `~` 授权给文件系统服务器，等于把 SSH 私钥、浏览器配置和机器上所有其他项目一起暴露。

**修复:** 每个服务器只授权一个项目目录；确实需要第二个范围就再配一个服务器。

### TW407 — 动态代码求值

`eval`、`new Function`、`pickle.loads` 和不安全的 YAML 会把数据变成代码，而这正是注入载荷所需要的。

**修复:** 用数据解析器解析数据（`JSON.parse`、`yaml.safe_load`、`json.loads`），彻底去掉 eval 这条路径。

**参考:** <https://cwe.mitre.org/data/definitions/95.html>

## 网络与数据外带

| 规则 | 默认严重度 | 标题 |
| --- | --- | --- |
| `TW501` | 严重 | 外连到数据落地/隧道类服务 |
| `TW502` | 中危 | 硬编码 IP 端点 |
| `TW503` | 高危 | 被混淆的载荷 |
| `TW504` | 严重 | 运行时执行远程内容 |
| `TW505` | 高危 | 带外数据外带原语 |

### TW501 — 外连到数据落地/隧道类服务

这些端点的存在意义就是接收别人发给它的任何内容，因此天然成为被窃取上下文的默认去处。

**修复:** 删掉该端点。开发期确实需要回调地址时，也不要提交进配置。

### TW502 — 硬编码 IP 端点

裸的公网 IP 没有证书身份、查不到归属，无法像域名那样被审核。

**修复:** 改用带 TLS 的域名；若地址必须固定，请写明原因。

### TW503 — 被混淆的载荷

扩展里的长编码块，恰好把审阅者最需要读的内容藏了起来。

**修复:** 解码后把明文源码提交进来；或者写清楚这段编码块是什么、从哪来。

### TW504 — 运行时执行远程内容

先下载代码再求值，意味着你审过的版本和实际运行的版本永远不是同一个。

**修复:** 把代码随包发布并用校验和验证；绝不要对网络响应做求值。

### TW505 — 带外数据外带原语

裸 socket、`/dev/tcp`、DNS 编码查询，可以在封禁普通 HTTP 出网的网络里把数据带走。

**修复:** 删掉。正经扩展只会访问有文档的 HTTPS API。

## 治理与卫生

| 规则 | 默认严重度 | 标题 |
| --- | --- | --- |
| `TW601` | 低危 | 扩展缺少来源元数据 |
| `TW603` | 中危 | 跨服务器的重名工具 |
| `TW604` | 中危 | 工具名遮蔽了宿主内置工具 |
| `TW605` | 低危 | Skill 隐式获得执行权但未声明 |
| `TW606` | 提示 | 工具面未锁定，无法发现静默变更 |
| `TW602` | 严重 | 工具面在批准之后发生了变化 |

### TW601 — 扩展缺少来源元数据

没有作者、仓库或许可证信息，扩展一旦出问题，你连该通知谁都不知道。

**修复:** 在清单里补上 `author`、`repository`/`homepage` 和 `license`；skill frontmatter 补上 `name` 与 `description`。

### TW603 — 跨服务器的重名工具

两个服务器暴露同名工具时，agent 按顺序挑一个，后装的那个可以悄悄接管已有调用点。

**修复:** 给工具名加命名空间，或者删掉其中一个服务器。

### TW604 — 工具名遮蔽了宿主内置工具

叫 `read_file` 或 `bash` 的工具会与宿主同名工具竞争，可能截获本该发给宿主的调用。

**修复:** 给工具名加上产品前缀，例如 `acme_read_file`。

### TW605 — Skill 隐式获得执行权但未声明

正文里会跑 shell 命令、却没声明 `allowed-tools` 的 skill，会直接继承当前会话已有的全部权限。

**修复:** 声明该 skill 真正需要的最小 `allowed-tools`，例如 `Bash(git status:*), Read`。

### TW606 — 工具面未锁定，无法发现静默变更

没有锁文件就没有比对基准，服务器在你批准之后偷偷改掉工具描述（rug pull）你不会察觉。

**修复:** 执行 `toolward lock` 记录当前工具面，把锁文件提交进仓库，并在 CI 里跑 `toolward verify`。

### TW602 — 工具面在批准之后发生了变化

服务器完全可以在你审核当天给一份无害描述，一周后换成恶意的。只有与已提交的锁文件比对，才能发现这件事。

**修复:** 先审阅 diff 再接受。变更确属正常的，重新执行 `toolward lock` 并提交新锁文件。

**参考:** <https://invariantlabs.ai/blog/mcp-security-notification-tool-poisoning-attacks>
